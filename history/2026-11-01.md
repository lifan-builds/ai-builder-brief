## Top 10

1. **Jepsen finds 96 ParticleDB failures and challenges AI-era quality claims** — **October 31 report; experiments conducted before publication**. Testing versions 1.1.4 through 1.1.18.11.rc-22 uncovered 96 issues, all but three on healthy single nodes, including lost writes and broken constraints; Orkes says 1.1.19-rc.13 fixes everything, but Jepsen has not tested it. The newly published analysis explains how roughly 2,000 lines of generative differential tests exposed failures beneath expansive documentation and repeated LLM claims that bugs were fixed. Require reproducible behavioral tests and verify that deliberately broken implementations fail them before trusting generated infrastructure. This case does not establish that AI caused every defect; production users largely ran an older version, and replication was not tested. [Full analysis and vendor response](https://jepsen.io/analyses/particledb-1.1.4) · [Test harness](https://github.com/jepsen-io/particledb) · [Willison’s reaction](https://simonwillison.net/2026/Nov/1/kyle-kingsbury/).

2. **DeepSeek opens a proactive-agent prototype that budgets human attention** — **October 31, 09:32 UTC repository creation; October 31 design publication**. The MIT-licensed dsh-superagent watches one GitHub repository and optionally Feishu, routes authorized requests into separate worker sessions/directories, and returns results to the originating conversation. Its concrete design separates incoming context from authority, defaults inferred work to observation, and revalidates mandates before resuming; the panel emphasizes work needing people. Test this admission-and-resumption model before enabling unsolicited work, and enforce merge requirements through branch protection. The repository is about one day old, with visible forks but no verified deployment series; it differs from DeepSeek’s internal system, includes unfinished ideas, and explicitly says command wrappers/directories are not security boundaries. [Primary prototype](https://github.com/deepseek-ai/dsh-superagent-prototype) · [Authorization design](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/002-authorization.md) · [Chinese publication confirmation](https://www.yicai.com/brief/103419783.html).

3. **Prospero turns blocked commands into resumable work with bounded waits** — **October 31 engineering account; repository created October 21**. Chris Wellons explains a native C++ harness built around deadlines: permission requests time out to denial, long shell commands become background jobs, and stopping commands terminates their process trees. Passive rendering avoids continuously redrawing an idle interface, while detachable engines support remote work; the free Community build omits bundled remote engines included in Professional. Try fault-injecting network stalls, absent approvers and slow builds into your harness, checking that work resumes without duplicate processes. This is a newly published implementation explanation, not evidence of widespread migration; the author’s roughly hundredfold resource claim lacks an independently reproduced comparison, and Plan mode deliberately permits indefinite waiting. [Full design account](https://nullprogram.com/blog/2026/10/31/) · [Implementation and documentation](https://github.com/skeeto/prospero).

4. **Memdoor publishes small-model team traces that expose reviewer-induced regressions** — **October 31–November 1 result documentation and workflow updates; repository created October 5**. A reproduction of GVS5H’s planner/ideator/solver/manager loop reports 49 successes in 50 runs across ten LiveCodeBench Hard problems repeated five times, with requests, programs and hidden-test verdicts published. Median model time was 40 minutes and median cost $0.39; one failure followed a reviewer inventing a wrong counterexample and replacing correct code, while two other regressions recovered expensively. Try checking generated counterexamples with brute force and retaining successful candidates. This is maintainer-reported replication, not a general frontier-model win: problems may be contaminated, the Fable comparison uses another harness’s single calls, and the broader original study’s gap is much smaller. [Workflow, scope and results](https://github.com/guregodevo/memdoor/tree/main/examples/workflows/team-solve) · [Failure traces and host differences](https://github.com/guregodevo/memdoor/blob/main/examples/workflows/team-solve/NOTES.md).

5. **SAM traces Gemini-wide prompt failures to one transformed MCP schema** — **November 1 retrospective; fix merged October 31, 18:02 UTC**. Simple Agent Manager found that OpenCode converted nullable JSON Schema type arrays into `anyOf` while retaining sibling fields, producing a shape Vertex rejected before inference. One invalid tool field rejected the entire declaration list; scanning 149 tools found 42 offending nodes across twelve tools, prompting rewritten nullable branches and tests before and after the adapter transformation. Validate the provider-bound representation, preserve redacted error detail, and test the failure with the old shape restored. This January-created project supplies code and a concrete incident, not adoption telemetry; its regression suite models the adapter, and the PR explicitly leaves the live Vertex path unverified. [New technical explanation](https://www.simple-agent-manager.org/blog/json-schema-isnt-always-portable/) · [Incident, implementation and verification limits](https://github.com/raphaeltm/simple-agent-manager/pull/2483).

6. **OpenAI plans shared ChatGPT and Codex allowances starting in December** — **Documented publicly by October 31; help page has no original publication timestamp**. OpenAI says Plus, Pro and Business will share a token-measured allowance across ChatGPT and Codex as Work capabilities enter the main ChatGPT experience; Instant chat will not consume it. Model choice and task complexity affect consumption, with combined remaining usage/reset times planned for Settings and credits available for eligible features after limits. Builders should budget interactive reasoning and coding together and measure their own mix before assuming today’s separate capacity carries forward. This is a future transition, not a live December rollout; OpenAI predicts most users will not wait more often but supplies no universal numerical allowance in this notice. [Primary transition terms](https://help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits) · [Dated community discussion](https://community.openai.com/t/banked-reset-1-day-27-of-28-days-of-quality-of-life-improvements-and-or-a-full-reset/1403525?page=7).

7. **Talos finds malware using models to prioritize stolen victims’ assets** — **October 31, 08:00 report; sample first seen October 11**. Cisco Talos’s newly published VOLTA analysis describes an optional post-theft LLM stage that assembles stolen information into an assessment of monetizable assets, with fallback models when responses refuse. The important operational change is automating sustained analysis after collection, rather than merely generating malware code; the sample can operate without the AI stage. Defenders should account for session-driven enrichment and inference requests alongside collection and exfiltration, using the report’s observable workflow and sample indicators. Talos provides reverse-engineering evidence, but not campaign prevalence, measured criminal returns or proof that every configured model call succeeds; this publication does not date the malware’s creation to today. [Primary analysis, indicators and limitations](https://blog.talosintelligence.com/appraisal-by-ai-model-driven-victim-prioritization-in-the-volta-infostealer/).
