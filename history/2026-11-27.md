## Top 10

1. **Datadog open-sources Ephyra, an agentic property-based tester finding 70+ SQLite bugs**
   `Developer tools & agents` · Datadog Systems Research · MIT · [datadog-labs/ephyra](https://github.com/datadog-labs/ephyra)
   - **What happened:** Datadog Systems Research released MIT-licensed `ephyra` (`v0.0.1` Rust library plus `ephyra-cli`), combining property-based testing with inductive hill-climbing where coding agents rewrite test-case generators from code-coverage feedback rather than mutating individual inputs. Ephyra runs surfaced `70+` bugs in SQLite, `20` in PostgreSQL, and `25` in Lean, while its autonomous agent found defects in FoundationDB, TigerBeetle, OCaml, LiteLLM, FastMCP, and Bun; failures print a shrunk counterexample and an `EPHYRA_REPLAY=<seed>:<iteration>` line that reruns that exact case, with failing cases remembered in `.ephyra/regressions/` so the next run tries them first.
   - **Builder move:** Install `ephyra-cli` and point a coding agent at `README.md` and `STARTUP.md` on one parser, state machine, or storage invariant to turn fuzzing runs into repeatable regression tests.
   - **Caveat:** Almost all code in the repository is experimental and subject to change (`ephyra` is at `v0.0.1`); `case-studies/sqlite/vendor/fetch.sh` pulls SQLite trunk for the SQLite and Turso case studies, while `turso/differential`, `turso/apidiff`, and `cedar/generator` require separate target checkouts at the repo root.

2. **Apache Airflow CVE-2026-120353 exposes worker RCE across common.ai LLM and agent decorators**
   `Security & policy` · Nov 26 · MITRE CVE (`Claude Security Scans`, `Sonar`) · [CVE-2026-120353](https://cveawg.mitre.org/api/cve/CVE-2026-120353)
   - **What happened:** Apache disclosed `CVE-2026-120353` affecting `apache-airflow-providers-common-ai` (`v0.1.0` to `<v1.2.0`), `standard` (`v0.3.0` to `<v1.22.0`), `cncf-kubernetes` (`v10.5.0` to `<v11.0.0`), and `common-sql` (`v1.32.0` to `<v3.0.0`), where TaskFlow decorators—including `@task.llm`, `@task.agent`, `@task.llm_sql`, `@task.llm_branch`, `@task.llm_file_analysis`, and `@task.llm_schema_compare`—rendered Jinja templates a second time on workers. Any attacker who can trigger a DAG run (`run conf`) or control text passed into an affected decorator's `env`, arguments, or prompt (such as a ticket or downloaded document) can execute arbitrary commands on the worker and read connection passwords and Airflow Variables.
   - **Builder move:** Upgrade `apache-airflow-providers-common-ai` to `v1.2.0`, `standard` to `v1.22.0`, `cncf-kubernetes` to `v11.0.0`, and `common-sql` to `v3.0.0` or later immediately.
   - **Caveat:** Exploitation applies only to deployments using an affected decorator in a DAG that passes trigger `run conf` or attacker-controlled text through `env`, parameters, or prompts.

   `Models & APIs` · LlamaIndex · CPU & Wasm pipeline · [llamaindex/OCRia-nano-1](https://huggingface.co/llamaindex/OCRia-nano-1), [run-llama/liteparse](https://github.com/run-llama/liteparse)

   `Research & evaluation` · `arXiv:2611.34232` · `300` v1 tasks (`6` platforms) · [OS-Omni (arXiv:2611.34232)](https://arxiv.org/abs/2611.34232), [OS-Copilot/OS-Omni](https://github.com/OS-Copilot/OS-Omni)

8. **Stable GDN-2 mitigates Gated DeltaNet-2 state blow-ups, lifting 128K RULER by 6.80 points**
   `Research & evaluation` · Nov 25 · `arXiv:2611.34051` · [Stable Gated DeltaNet-2 (arXiv:2611.34051)](https://arxiv.org/abs/2611.34051)
   - **What happened:** Researchers traced long-context training failures in Gated DeltaNet-2 (`GDN-2`) to asymmetry between reading and modification directions during erasure, producing non-normal erase operators whose directional gains can accumulate exponentially when amplified state directions align with subsequent expanding directions, even without new writes. Replacing that update in `Stable GDN-2` with symmetric erasure (under standard key normalization and gate constraints) plus decay-regulated residual writing establishes an `O(sqrt(T))` upper bound on recurrent state growth while retaining chunkwise parallel computation, lifting `128K` average `RULER` by `+6.80` points on `1.6B`-parameter recurrent models (`11.62` vs. `4.82`) and boosting nine-task hybrid accuracy by `+0.62` percentage points.
   - **Builder move:** Audit GDN-2 and related linear-attention training stacks for asymmetric erase operators before extending sequence lengths to `128K` tokens.
   - **Caveat:** Reported experiments stop at `1.6B`-parameter models, leaving training stability at frontier model scales untested.

9. **12,384-trial database agent audit shows engine undo controls surviving damage**
   `Security & policy` · Nov 23 · `12,384` trials · MIT harness · [Database blast-radius (arXiv:2611.30483)](https://arxiv.org/abs/2611.30483), [libredb/agent-blast-radius](https://github.com/libredb/agent-blast-radius)
   - **What happened:** A preregistered two-layer study scripted `22` canonical database mistakes across four relational engines under five permission and two recovery arms (`792` cells, `874` recovery drills), then ran `12,384` live tool-calling agent trials (`9,468` across PostgreSQL, MySQL, SQLite, ClickHouse, Cassandra, MongoDB, Valkey, Kafka, and OpenSearch plus `2,916` on MariaDB, Redis, and Elasticsearch) archived on Zenodo. Scoring loss that survives each engine's native undo drill finds engines differ less in what a mistake destroys than in what they let operators undo; only `3/7` preregistered hypotheses met their decision rule, and `H4` (whether attempted damage varies more across engines than across models) met its rule under the preregistered measure but not once requested writes were excluded.
   - **Builder move:** Test engine-native undo and recovery drills and enforce least-privilege database roles before granting agents write access rather than relying on prompt rules alone.
   - **Caveat:** Layer B evaluated six small locally served open-weight models (`4B` to `12B` parameters plus a `35B` MoE with `~3B` active) rather than frontier models, and four of seven preregistered hypotheses did not meet their decision rule.

10. **Jarred Sumner details shipping Bun's multi-million-line agent-written AOT compiler cutting memory 4x**
    `Builder behavior` · Nov 24 · `AI Engineer` (`48.8K+` views) · [How to Ship Millions of Lines of Agent-Written Code](https://www.youtube.com/watch?v=TvsF67C2F54)
    - **What happened:** Bun creator Jarred Sumner (Anthropic) detailed merging a PR of several million agent-written lines adding an ahead-of-time compiler to Bun—the runtime behind Claude Code—after `five` rewrites in about a month, alongside a walkthrough of what he does all day with `140` agents at once. Choosing to make JavaScript faster instead of rewriting Claude Code in Rust cut memory use by `~4×` and sped startup `~2×`, using tests that predate the project to keep agent-written compiler code trustworthy.
    - **Builder move:** Anchor large agent-written rewrites to test suites that predate the refactor and plan for multiple rewrites rather than patching a weak first pass.
    - **Caveat:** Claims are drawn from Sumner's conference talk metadata, which links only his X profile and `bun.sh` without a public benchmark harness or standalone AOT PR diff.
