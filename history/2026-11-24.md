## Top 10

1. **Autonomous Cairn agents discover and exploit MONAI Label zero-day CVE-2026-133968 in eleven minutes** — **November 23, 2026 CISA KEV addition (due November 26 under BOD 26-04 with mandatory forensic triage; November 20 AWS Threat Intelligence report & November 18 `GHSA-qc22-rmgc-vg94`)**. Analyzing an unauthenticated `Cairn` penetration-testing server left exposed online during a September 8–10, 2026 campaign against East Asian universities, Amazon Threat Intelligence documented AI agents given only target IPs and the plain-language prompt `"obtain shell access"`. After running continuously for 16 hours (148 sequential actions) against a hardened Redis host and testing 30,000+ credentials across 80 scraped usernames on a GPU cluster without breaking in, the agents pivoted to a medical-imaging AI server running `Project MONAI`'s `MONAI Label <= 0.8.5`. Within roughly 11 minutes, the agents mapped the REST API, found an unvalidated `image` query parameter on `PUT /datastore/image` (`LocalDatastore.add_image()` and `PUT /datastore/label` joining untrusted IDs directly into `shutil.copy()`), wrote a Python reverse shell into `sitecustomize.py`, and called a training endpoint to spawn a fresh Python interpreter running as `root`—taking advantage of `MONAI_LABEL_AUTH_ENABLE=False` by default. Operators hosting `monailabel` must upgrade immediately to `0.8.6` (`PR #1915`), enforce authentication, run inference/labeling daemons as non-root users, and audit exposed AI tooling endpoints under automated containment rather than manual alert triage. Two operational caveats frame the disclosure: the victim server ran with default disabled auth and root privileges, and Amazon's Chinese-nexus attribution rests on moderate-confidence indicators (Simplified Chinese prompts, China Standard Time script timestamps, and target selection). [AWS Threat Intelligence Cairn report](https://aws.amazon.com/blogs/security/chinese-nexus-actors-cairn-ai-agents-found-a-zero-day-on-their-own/), [MONAI Label GHSA-qc22-rmgc-vg94](https://github.com/Project-MONAI/MONAILabel/security/advisories/GHSA-qc22-rmgc-vg94).

2. **OpenAI and Cisco open-source Shirudo eBPF runtime for signed zero-restart Linux shields** — **November 23, 2026 primary open-source release (21:20 UTC; 79 HN points, 24 comments)**. Answering the gap between machine-speed exploit discovery and multi-week fleet patching cycles, OpenAI and Cisco published `shirudo-dev/shirudo`, a Linux security runtime that loads cryptographically signed eBPF or Java micropatches (`upatches`) from OCI registries without restarting production services. In OpenAI's controlled demonstration, a Codex-generated shield blocked a `Java4Shell` exploit against a live Elasticsearch node while letting legitimate traffic pass. At boot, `shirudo init` attaches kernel guards from the `initrd` so even a compromised `root` user on the target cannot strip protections without the operator's signing key; the kernel verifies every eBPF loader against a sealed `.bpf` keyring, every load or unload extends a per-boot TPM 2.0 register for offline `shirudo attest` verification, and teams can dry-run shields in observation mode via OpenTelemetry before enforcing. Platform and security engineering teams can test the local software-TPM VM quickstart and `kernel-obs` package today to evaluate live virtual patching for long-lived servers and LLM agent hosts. Deployment constraints are steep for now: `Shirudo` is pre-release, production targets require custom kernel patches supporting the signed-loader ABI plus hardware TPM 2.0, and CI validates `x86-64` and `arm64` while `riscv64` remains pending. [OpenAI Shirudo announcement](https://openai.com/index/introducing-shirudo/), [shirudo-dev/shirudo repository](https://github.com/shirudo-dev/shirudo).

3. **Anthropic launches Claude Ship beta with PR Steward and policy-driven Claude Approvals** — **November 23, 2026 primary product launch**. Targeting the pull-request review bottleneck created by high-volume coding agents, Anthropic shipped `Claude Ship` in beta for Claude Team and Enterprise GitHub repositories, combining generally available `Code Review` (`Quick`, `Standard`, and `Deep` tiers) with two new beta agents: `PR Steward` and `Claude Approvals`. Invoked per branch via `/ship` in Claude Code or enabled repo-wide by admins with monthly spend caps, `PR Steward` monitors open PRs, pushes commits to fix failing CI checks, merge conflicts, and human or automated review feedback, comments with exact revert instructions, responds to `@claude` steering or `@claude stop`, and explicitly holds no approve or merge rights. `Claude Approvals` evaluates diffs against a natural-language policy file committed on the default branch—acting like a programmable `CODEOWNERS` layer that can auto-approve routine changes or escalate risky paths to human reviewers. Anthropic reports that layering Claude review inside its own Claude Code repo coincided with merged PR volume more than doubling from June to September while revert share fell over 40%, and is offering eligible Enterprise orgs at least `$10,000` in credits (claimable through January 15, 2027, valid 30 days). Engineering leaders testing automated PR triage should start `Claude Approvals` in observe-only mode alongside existing branch protection before granting approval authority. Access excludes Free/Pro individual plans, requires GitHub repositories, and lacks published per-PR token-cost curves across the three review depths. [Introducing Claude Ship](https://claude.com/resources/articles/introducing-claude-ship).

4. **Google DeepMind open-sources Lean 4 quantum verification suite after cutting circuit costs 290x** — **November 23, 2026 primary release and repository (16:59 UTC; `arXiv:2611.09822`)**. Because resource-intensive quantum algorithms exceed classical simulation and today's noisy processors, Google DeepMind and Google Quantum AI built `google-deepmind/formal-quantum-computation`, a Lean 4 framework grounded in quantum Hoare logic with classical variables (`QuantumComputation` core library, `QuantumComputationSpecs` challenge suite, and `discoveries` branch). Independent teams of Gemini 4 agents proposed algorithmic improvements, proved correctness and resource bounds in Lean 4 before committing entries to a shared notebook, and convened at four-hour virtual conferences to critique and combine techniques. Across five benchmark targets, verified discoveries cut computing cost (qubits × operations) by `11.8×` for inertial confinement fusion (`5,650` down to `4,338` error-corrected qubits), `8×` for a photochemical molecule simulation, `2.5×` for Cytochrome P450 (`481` down to `333` qubits by eliminating bulky memory lookups), `2.57×` for parallel Grover search, and `290×` for quantum `arcsin` state preparation. Formal-methods and AI-for-science engineers can clone the `lake`-managed repository (`lake exe cache get && lake build`) to benchmark automated theorem-proving agents against formally costed specifications. Even with order-of-magnitude savings, the resulting circuits still exceed first-generation fault-tolerant hardware, and the open Lean framework does not yet include explicit cost models for classical co-computation or control flow. [DeepMind quantum verification post](https://deepmind.google/blog/finding-faster-quantum-algorithms-with-agents-and-formal-verification/), [google-deepmind/formal-quantum-computation](https://github.com/google-deepmind/formal-quantum-computation).

5. **Anthropic releases AI-authored VP ≠ VNP proof and Lean 4 formalization checked by nanoda** — **November 23, 2026 open-source research artifact (20:04 UTC commit; 343 HN points, 311 comments)**. Anthropic published `anthropics/formal-math/tree/main/vp-vnp` under Apache-2.0 containing `paper.pdf` and a full Lean 4 formalization authored by an internal research Claude model claiming that algebraic circuits for the Hamiltonian cycle polynomial—and for the permanent outside characteristic 2—require more than `m^(c (log m)^(1/3))` gates for large `m`, separating `VP` from `VNP` (and its border closure) over every field. Reproducible verification (`lake build` plus `scripts/PrintAxioms.lean`) relies solely on standard Mathlib axioms (`propext`, `Classical.choice`, `Quot.sound`), and repository CI (`comparator-check.sh`) validates statement equivalence against `Challenge.lean` while re-checking the proof on an independent Lean kernel (`nanoda`). Researchers auditing AI-generated mathematics can inspect `Statement.lean` and Appendix Q (`Table 3`) locally rather than trusting summary claims. Three critical caveats apply immediately: Anthropic explicitly notes that no human mathematician has audited the proof, machine checking cannot verify that `Statement.lean` faithfully encodes the natural-language theorem (Table 3 explicitly documents divergences between paper statements and Lean counterparts), and the repository is unmaintained and does not settle `P vs NP`. [anthropics/formal-math/vp-vnp](https://github.com/anthropics/formal-math/tree/main/vp-vnp).

6. **Nari Labs ships 2.5–3 bit NariQ GGUFs matching BF16 Qwen3.8-27B on DeepSWE** — **November 23, 2026 HN surge (181 HN points, 35 comments; November 20 Apache-2.0 weights, `arXiv:2611.26157`)**. Observing that low-bit quantizers calibrated on short web text collapse to `<=72%` of BF16 solve rates on 100K+ token coding sessions even while matching BF16 on AIME, Nari Labs released `NariQ`, a trellis-coded post-training quantization method calibrated directly on BF16 coding-agent traces. Shrinking `Qwen3.8-27B` from `53.8 GB` BF16 to `10.12 GB` (`3.0 bpw`) and `8.44 GB` (`2.5 bpw`, plus a `0.93 GB` BF16 vision projector) matches or slightly edges BF16 under Claude Code `2.1.309` at `262,144`-token context (`temp=1.0`, `top-p=0.95`): `41.0%` (`3-bit`) and `41.9%` (`2.5-bit`) vs. `39.8%` BF16 on `DeepSWE v1.1` (113 tasks × 3 rounds, with `82.9%` and `83.2%` test pass rates vs. `83.1%` BF16), `63.8%` (`3-bit`) vs. `62.6%` BF16 on `Terminal-Bench 2.1` (`82 × 3`), `98.3%` vs. `97.7%` on `AIME 25+26`, and `82.4%` identical on `RealWorldQA`. Local-model builders running 12–16 GB NVIDIA GPUs can test the `3.0` or `2.5 bpw` builds immediately via `nari-labs/nari-llama.cpp` (`b12431-nariv0`). Practical friction remains: weights require Nari's custom `llama.cpp` fork on Linux with NVIDIA driver `>=570` rather than upstream `llama.cpp`, and the `2.0 bpw` (`6.75 GB`) build degrades sharply (`28.6%` DeepSWE, `52.4%` Terminal-Bench). [NariQ Qwen3.8-27B GGUF](https://huggingface.co/nari-labs/Qwen3.8-27B-NariQ-GGUF), [arXiv:2611.26157](https://arxiv.org/abs/2611.26157).

7. **QwenCloud launches qwen-audio-3.1-live full-duplex voice API with async backend delegation** — **November 23, 2026 primary API release**. Alibaba's QwenCloud added `qwen-audio-3.1-live` in Singapore and China North 2 (Beijing), exposing a full-duplex speech-to-speech model designed to keep conversing naturally with a user while either the caller's application (`Client` mode) or a separate QwenCloud reasoning model (`Responses` mode) handles long-running function calls and returns updates to speak aloud. The frontend audio session accepts up to `65,536` combined tokens of system instructions and function schemas, supports text and audio inputs/outputs with tool calling, and bills by wall-clock session duration at `$0.000710/second` (`$0.0426/minute`, 3-second minimum) with delegated backend model tokens billed separately. Voice-agent builders evaluating low-latency conversational frontends paired with slow reasoning backends can test `Responses` mode without stitching separate ASR, TTS, and barge-in state machines. Pricing and feature boundaries warrant careful metering: silence, text turns, and idle connections all accrue full per-second charges (unlike OpenAI's `$0.02/minute` WebRTC Standby mode on `GPT-Live-1.1`), and structured outputs, context caching, built-in web search, and fine-tuning are unsupported. [qwen-audio-3.1-live documentation](https://docs.qwencloud.com/models/qwen-audio-3-1-live), [QwenCloud model changelog](https://docs.qwencloud.com/changelog/models).

8. **Ai2 releases RoboTrack-Bench and RoboTrack-15M, showing real manipulation drops tracking 6.6 AJ** — **November 23, 2026 primary release (17:20 UTC; code, datasets, and checkpoints live)**. Testing whether off-the-shelf video point trackers survive real robotic clutter and gripper occlusion, the Allen Institute for AI (Ai2) published `RoboTrack-Bench` (`307` human-verified clips and `2,522` tracks across DROID, Ego-Exo4D, MolmoAct 2, and EgoVerse, including `33` synchronized dual-camera pairs) alongside `RoboTrack-15M`, a synthetic training set rendered in `MolmoSpaces`. Every evaluated baseline—`CoTracker3`, `BootsTAPNext`, `AllTracker`, and `CoWTracker`—dropped `3.0–6.6` Average Jaccard (`AJ`) moving from tabletop `RoboTAP` to `RoboTrack-Bench` (`CoWTracker` fell from `70.5` to `63.9`), while simulated `RGB-Stacking` actively inverted rankings (`BootsTAPNext` gained `+5.1 AJ` on `RoboTrack-Bench` from 15M real videos yet dropped `-9.5 AJ` on `RGB-Stacking`). Fine-tuning on `RoboTrack-15M`—after fixing point sampling to focus on moving robot arms and manipulated objects rather than static walls—lifted `RoboTracker` (`17M` params, AllTracker base) to `63.4 AJ` (`+0.8`) and `RoboTracker-Warp` (`~1B` params, CoWTracker base) to `66.0 AJ` (`+2.1`), setting SOTA on four of five benchmarks and guiding single-demo wet-lab pipetting. Robotics perception teams can swap in `allenai/robotrack` and re-benchmark existing trackers on `RoboTrack-Bench`. Note the licensing split before commercial deployment: `RoboTracker-Warp` checkpoints are restricted to noncommercial use, and `AllTracker` comparison scores required fixing a bug in upstream's evaluation script. [Ai2 RoboTrack release post](https://huggingface.co/blog/allenai/robotrack), [allenai/robotrack repository](https://github.com/allenai/robotrack).

9. **Embo-Harness lifts frontier-model robot policies to 83.3% on RoboLab-120 via spatial targets** — **November 24, 2026 #1 Hugging Face Daily Paper (88 upvotes; `arXiv:2611.31201`, submitted November 23, code live)**. Investigating why frontier multimodal models succeed or stall when wired directly as closed-loop robot policies, researchers from NTU/S-Lab and collaborators built `Embo-Harness` (including an open server harness tested with `@openai/codex` `0.168.0`/`0.171.0`) and systematically ablated prompting, planning, action execution, and tool use. Replacing handcrafted sub-plans, rigid skills, and low-level joint or frame-wise trajectory generation with native visual reasoning and end-effector destination targets boosted success on the 20-task exploration split from `43.3%` to `96.7%`, reached `83.3%` across `RoboLab-120` (`+26.2` percentage points above the strongest prior baseline), and succeeded in `15/20` zero-shot real-world manipulation trials across four tasks. Embodied-AI engineers wiring VLMs or coding agents to robot controllers should expose high-level spatial destination primitives and short multi-action chunks instead of forcing LLMs to emit raw joint deltas. Hardware and reproducibility bounds remain tight: the Codex harness requires Linux sandbox support pinned to specific CLI builds, and physical validation spans only 20 tabletop trials rather than cluttered mobile manipulation. [arXiv:2611.31201](https://arxiv.org/abs/2611.31201), [DravenALG/Embo-Harness repository](https://github.com/DravenALG/Embo-Harness).
