1. **Z.ai launches GLM-5.4, looping 28 layers twice inside a 750B coding transformer** — **November 23, 2026 primary architecture release (405 HN points, 169 comments)**. Z.ai adapted its pre-trained 750B `GLM-5` base into a 78-physical-layer Loop Transformer (`L1–26` Prelude, 28 weight-shared `L27–54` blocks run twice for 106 effective layers, `L55–78` Coda, plus a 24-layer ViT projection) aimed at long-chain software, CAD, game, and shader generation. Three design changes keep serving viable at 1M context: per-token Damp Gates (`x_1 = x_0 + β_1(h_1 - x_0)`) stop activation norms from exploding across passes, Two-Bank Sparse MLA reuses Pass 1's `k = 2048` top-k KV latent cache while adding only a `128`-token Pass 2 sliding window, and Pass 2 drops the sparse indexer entirely to reuse Pass 1 indices at zero indexing cost. Fused serving kernels hit up to `200 tok/s` off-peak and `70–80 tok/s` under peak load. In a controlled 30B iso-parameter ablation after 200K SFT (~10% extra training compute), looping raised `AIME25` from `19.17` to `30.42` (`+11.3`), `GPQA-Diamond` from `47.58` to `56.26` (`+8.7`, cutting output length `11.7%`), `AA-LCR` from `40.33` to `47.67` (`+7.3`), `MMLU-Pro` from `71.65` to `75.05` (`+3.4`, `-14.9%` tokens), and `IFBench` from `50.20` to `53.47` (`+3.3`, `-13.0%` tokens). Teams evaluating `GLM-5.4` should test it today in Z.ai Chat, ZCode, or the GLM Coding Plan while tracking API release timing (`z.ai/model-api` still listed as coming soon) and planned open weights after safety hardening. Two caveats remain at launch: Z.ai warns the model can enter long "marathon thinking" loops, and full 750B coding benchmark tables remain unpublished. [Z.ai GLM-5.4 release post](https://z.ai/blog/glm-5.4).

2. **OpenAI Chief Scientist publishes internal perplexity curve and proposes shared lab ceilings** — **November 22, 2026 primary safety and research disclosure (633 HN points, 414 comments)**. OpenAI Chief Scientist Jakub Pachocki published OpenAI's held-out internal-codebase log-perplexity (cross-entropy loss) trajectory across model generations, arguing that pretraining compression loss remains durable even as downstream evals saturate. On OpenAI's fixed internal codebase snapshot, `GPT-3.5` sat near `~0.99` (fluent chat), `GPT-4` near `~0.91` (productive chain-of-thought), sub-`0.8` unlocked cybersecurity and mathematics capabilities, and crossing `~0.76` produced resolutions to open math problems inside a single internal Slack thread. Extrapolating into the `~0.68–0.70` band—and noting AI design contributions already aided OpenAI's 2026 acceleration—Pachocki warns an avalanche of automated pretraining advances could arrive by 2027 while chain-of-thought monitors degrade and evaluation awareness grows. He proposes binding cross-lab development limits tied to concrete monitoring milestones (such as a verified successor to CoT monitors). AI safety, red-teaming, and governance teams should benchmark base-model cross-entropy on shared public corpora alongside capability suites rather than trusting downstream task scores alone. As Pachocki notes, four measurement constraints limit direct enforcement: labs evaluate on mismatched private corpora, test-time CoT compute boosts capability without changing base perplexity, the true entropy floor of text/code is unknown, and no other frontier lab has yet signed on to a common corpus or pause trigger. [OpenAI Perplexity and Intelligence](https://openai.com/index/perplexity-and-intelligence/).

3. **OpenCode v2.4.0 embeds a persistent desktop browser, scheduled `/automation`, and `generate_video`** — **November 23, 2026 open-source release (09:22 UTC)**. Coding-agent harness `anomalyco/opencode` shipped `v2.4.0` with a built-in desktop browser (`#63002`, `#65073`) that imports sign-ins, browsing history, and Chromium extensions from Chrome, Edge, Firefox, or Safari into one persistent profile so agents can inspect and drive authenticated pages beside the chat pane. A new `/automation` scheduler (`#65296`, `#65186`, disableable via `"automations": false`) triggers prompts, scripts, or shell commands on timers, cron schedules, or incoming MCP server events, while `generate_video` (`#63666`) renders workspace videos asynchronously on supported providers and `experimental_image_generate` graduates to `generate_image` (`#65682`). Operational breaking changes require immediate config checks: GitHub Copilot no longer reads `GITHUB_TOKEN` (requiring `COPILOT_GITHUB_TOKEN` or OAuth, `#64697`), version-range plugins (`name@latest`, `name@^1.2.0`, Git branches) now auto-update on startup and every 24 hours, MCP servers probe the newest protocol first (`protocol: "legacy"` restores legacy handshakes, `#65282`), and Code Mode session paths move to `tools.opencode.session.rename` and `.move` (`#65080`). Teams upgrading desktop workflows should add a `browser` deny permission rule where agents must not touch imported sessions, migrate Copilot scripts to `COPILOT_GITHUB_TOKEN`, and pin exact plugin versions or commit hashes where unattended 24-hour updates violate change control. 4. **Upload2Shell (`CVE-2026-125396`) escapes Ghostscript `-dSAFER` across AI image servers and web pipelines** — **November 21, 2026 HN security surge (153 HN points, 77 comments; rolling disclosure after Nov 9 CVE & Nov 10 Google fix)**. Researcher Paulos Yibelo (`pwn.ai`) detailed `Upload2Shell` (`CVE-2026-125396`, `Artifex Bug 709684`), a use-after-free in Ghostscript's Type 1 font loader that breaks out of `-dSAFER` to execute arbitrary commands as the rendering process—even when EPS bytes are uploaded as `.png` or `.jpg` and forwarded via Pillow or ImageMagick. The public record documents confirmed execution or bounded worker file reads across ten software targets and Google's production document pipeline (mitigated November 10), including unauthenticated Debian 13 CUPS IPP jobs (`lp`), WordPress Core (`CVE-2026-65640`), Roundcube (`CVE-2026-114727`), Plesk Obsidian, Elementor, Forminator, Mayan EDMS, DokuWiki, and MediaWiki PdfHandler. For AI builders, `pwn.ai` verified a live unauthenticated HTTP-to-`gs -dSAFER` handoff on `Gradio 6.32.0` (`Pillow 13.0.0`, Ubuntu 24.04) and mapped Pillow upload/preview sinks in pinned revisions of `ComfyUI`, `InvokeAI`, `AUTOMATIC1111 Stable Diffusion WebUI`, and `CVAT`. Operators should patch immediately to Ghostscript `10.08.0`, Debian `10.05.1~dfsg-1+deb13u3`, or Ubuntu `USN-8949-1`, and strip `EPS`/`PS`/`PDF` delegates from ImageMagick/Pillow containers serving ML UIs. Scope caveats matter across targets: confirmed RCE proofs cover the first ten applications and Google, whereas `Gradio` verifies renderer handoff and `ComfyUI`/`InvokeAI`/`A1111`/`CVAT` remain source-mapped paths requiring Ghostscript on the host image. [Upload2Shell public record](https://pwn.ai/upload2shell), [Artifex Ghostscript 10.08.0 release](https://github.com/ArtifexSoftware/ghostpdl-downloads/releases/tag/gs10080).

5. **SkillPrivus audits 726 marketplace agent skills and flags privacy harms in 54.5%** — **November 23, 2026 arXiv announcement (`arXiv:2611.26747`, submitted November 19)**. IBM Research and University of Notre Dame researchers built `SkillPrivus`, a static pre-install auditor (`gpt-oss-120b`) that extracts data flows from both code and natural-language `SKILL.md` instructions and scores them against Contextual Integrity norms without executing the skill. Across 726 skills gathered from ClawHub, SkillsMP, `skills.rest`, Anthropic, and NVIDIA (563 completing personal-data analysis; 22,158 extracted data moves), `SkillPrivus` flagged 2,144 moves (`9.7%`) across `307/563` skills (`54.5%`), matching three blind STEM annotators on `83.2%` (`κ = 0.35`) of 311 sampled moves. Over half of violations (`54.2%`) came from handling data types absent from the skill's install description and `33.7%` from unexpected recipients—occurring inside routine read, save, and send steps rather than overt malware. Tellingly, `24/37` of NVIDIA's signed Verified Skills (already scanned by `SkillSpector` for security bugs) still triggered privacy-of-use flags. Platform teams running internal skill registries or MCP catalogs should audit actual file/network sinks against declared task scope before install instead of relying solely on malware scanners or install blurbs. Limitations are concrete: `SkillPrivus` relies on static LLM inference with moderate inter-annotator agreement (`κ = 0.35`), misses runtime-fetched payloads, and has not yet released its auditing code publicly. [arXiv:2611.26747](https://arxiv.org/abs/2611.26747).

6. **cmHC stabilizes 300B-MoE hyper-connections via Birkhoff contraction and cuts Ascend latency 44.8%** — **November 23, 2026 #1 Hugging Face Daily Paper (80 upvotes; `arXiv:2611.27193`, code released)**. Researchers from China Telecom's Xingchen AGI Lab, Huawei Technologies, HKUST(GZ), and HIT(SZ) diagnosed why DeepSeek-style Manifold-Constrained Hyper-Connections (`mHC`) stall or collapse: residual mixing matrices near Birkhoff polytope vertices under-mix into isolated streams, while matrices clustered near the uniform barycenter erase stream diversity. Their zero-extra-parameter fix, `cmHC`, geometrically contracts the Birkhoff polytope toward its interior (`λ = 0.97` at 6B, `λ = 0.96` at 300B) with gentler contraction in shallow layers to preserve gradient flow. On FineWeb-Edu DeepSeek-style 4-stream MoEs, `cmHC` beat `mHC` by `0.002` loss and `mHC-lite` by `0.005` at 6B (`71.5k` steps) and opened a `0.0157` loss lead over `mHC` on a 300B-MoE (`2k` steps) with smoother gradient norms. Fused Ascend C Pre/Post operators on an Ascend 910C (`CANN 9.1.0`, `B=1, S=4096, n=4`) cut isolated hyper-connection forward+backward latency by `44.8%` at `D=2,048`, `31.0%`, and `24.1%` at `D=7,168`. Pretraining teams experimenting with multi-stream residual architectures can drop `Newiz430/cmHC`'s `train_cmhc.py` (`--cmhc_gamma=0.97`) directly into PyTorch ablations. Two scope bounds apply: the 300B-MoE comparison stopped at 2,000 steps rather than full convergence, and the fused kernels target Huawei Ascend 910C NPUs rather than NVIDIA CUDA/Triton. [arXiv:2611.27193](https://arxiv.org/abs/2611.27193), [Newiz430/cmHC repository](https://github.com/Newiz430/cmHC).

7. **MemOnce cuts 1M-context KV cache 1,313x and prefill latency 6.9x via on-demand decoding** — **November 23, 2026 Hugging Face Daily Paper (13 upvotes; `arXiv:2611.27973`, submitted November 20)**. Seeking a middle ground between linear-growth KV caches and lossy fixed-state linear RNNs, Nie et al. (`arXiv:2611.27973`) propose `MemOnce`, pairing a Memory Encoder-Decoder that caches only a compact subset of final-layer hidden states (decoding per-layer KV caches on demand) with Memory Sparse Attention that computes retrieval indices once across all layers. Adapting `Qwen3.5-4B` with `MemOnce` shrinks the 1M-context memory state cache by `1,313x` and cuts prefill latency by `6.9x`, while lifting throughput `3.5x` and improving aggregate long-context memory performance by `+5.77%` with competitive zero-shot representation transfer. Serving and continual-agent architects fighting KV-cache OOMs on million-token histories should track single-index cross-layer retrieval and final-layer memory compression as a viable alternative to pure Mamba/GDN state compression. Practical adoption is blocked for now: the linked `Clare-Nie/MemOnce` GitHub repository currently holds no published weights or code, and reported 1M-context numbers come from an adapted 4B checkpoint rather than 30B–70B production serving stacks. [arXiv:2611.27973](https://arxiv.org/abs/2611.27973), [Hugging Face Daily Papers](https://huggingface.co/papers/2611.27973).

8. **Hugging Face publishes open agentic-eval playbook with Harbor `raman-lab` traces and checklist** — **November 23, 2026 primary engineering guide**. Pointing out that `98.2%` of model benchmark scores are still single-party reported—and `60%` of Artificial Analysis Intelligence Index v5 now relies on private test sets—Hugging Face's Avijit Ghosh, Ben Burtenshaw, and Irene Solaiman released a step-by-step manual for building auditable agent evaluations on top of the Hub's `~3,500` leaderboards and `~17,000` eval datasets (`16x` YoY growth). Using the new Hub `Traces`, `Benchmarks`, and `Environments` abstractions, the guide adapts Terminal-Bench's `raman-fitting` task into `raman-lab` (eight synthetic graphene Raman spectra packaged in `Harbor` format, run across six models in HF Jobs/Sandboxes with `Terminus-2` and exact provider-pinning syntax like `openai/Qwen/Qwen3.8-27B:deepinfra` via `router.huggingface.co/v1`). A concrete validation catch illustrates why trace inspection matters: an adversarial shortcut script reading raw peak heights passed all eight tasks without fitting curves until the authors added fit-quality assertions. Engineering teams building domain evals can clone the `raman-lab` Harbor setup and `.eval_results/` PR workflow to separate public harness/grader code from held-out private splits. Scope remains introductory: `raman-lab` covers only eight synthetic development tasks rather than noisy wet-lab spectra or multi-agent swarms. [Hugging Face agentic evaluation guide](https://huggingface.co/blog/agentic-evals).

9. **NoPeWorld reads frozen DiT activations to cut video world-model wall penetration from 74% to 16%** — **November 23, 2026 #2 Hugging Face Daily Paper (50 upvotes; `arXiv:2611.27963`, code, benchmark, and weights released)**. Hong Kong Polytechnic University's Learning & Generation Lab introduced `NoPeBench` and found that six open-source interactive video world models routinely drive right through solid obstacles (`74%` mean violation rate)—yet their frozen diffusion transformer (DiT) hidden states already encode impending collisions before frames are decoded, outperforming both VAE latents and pixel classifiers. `NoPeWorld` attaches a lightweight safety prediction head onto frozen DiT activations to flag unsafe candidate actions and substitute the closest collision-free action, cutting physical violation rates across the six models from `74%` down to `16%` while generalizing zero-shot to open-domain images, third-person viewpoints, and moving obstacles. Code (`yuhangdai427/NoPeWorld`), `NoPeBench`, and Hugging Face checkpoints (`PeterDAI/NoPeWorld`) are live today—simulation, robotics, and game-world builders should test the head as a low-overhead post-hoc guard without retraining base video generators. Practical limits remain: action rerouting operates over discrete candidate commands rather than continuous contact physics, and open-domain Task 3 evaluation relies on a VLM judge rather than a ground-truth 3D engine. [arXiv:2611.27963](https://arxiv.org/abs/2611.27963), [yuhangdai427/NoPeWorld repository](https://github.com/yuhangdai427/NoPeWorld).

10. **Audit of 938 Lean Reservoir packages shows AI proofs run up to 450x longer than human code** — **November 22–23, 2026 empirical ecosystem audit (167 HN points, 207 comments)**. Following weekend certification of Levent Alpöge's 17M-line Riemann Hypothesis formalization, developer `micjm` scraped all 259 human-authored Mathlib famous-theorem proofs alongside 938 GitHub-hosted Lean packages indexed on Reservoir to benchmark proof-size inflation empirically. No human-written theorem in Mathlib approaches 17M lines, whereas AI-generated repositories now dominate the upper tail: `Qiuzhen-CFSG/CFSG` reaches `88M` lines (still in progress), `CBirkbeck/LeanBridge` sits at `36M` (98% script-generated LMFDB number-checking tables; ~500K handwritten), and Anthropic's September `anthropics/fermats-last-theorem` spans `27M` lines—roughly `450x` the ~60K lines in Kevin Buzzard's ongoing human FLT project. Engineering teams adopting coding agents for formal verification should budget CI for multi-gigabyte build caches, long kernel-replay windows, and automated proof-compression passes rather than assuming human-readable diffs. However, raw line counts conflate verbose tactics, script-generated lookup tables, and comments without measuring compiled `.olean` term size or conceptual complexity. [micjm Lean proof-length audit](https://micjm.com/blog/yes-17m-lines-of-lean-is-a-lot/).
